# SimFarm native preservation

Reconstruct the supplied `../simfarm-dos/SIMFARM.EXE` incrementally as a native TypeScript/React/Vite browser game, using Bun for packages, scripts and tests. Do not run or embed a DOS/x86 emulator. Background music plays converted .mid files through libadlmidi-js’s light build with embedded bank 58 (WOPL, The Fat Man 2op set; user choice 2026-10-12, previously bank 39 AIL/SimFarm), as explicitly requested by the user. Music and sound effects must keep working on mobile browsers. This supersedes the earlier no-FM requirement; do not emulate the DOS environment. Keep simulation, asset decoding, audio, and UI separable for later enhancements.

- Inspect current files and `docs/progress.md` before continuing. Treat `../simfarm2` as incomplete research, not an implementation to copy wholesale.
- Ground recovered formats and rules in source bytes and executable addresses. Document offsets, hashes, hypotheses, and confidence in `docs`. Distinguish verified behavior from provisional scaffolding; do not declare a farming lookalike a completed port.
- Record original-game defects, overflow hazards and suspected vulnerabilities in the separate `docs/original-bugs.md` document, even after fixing them. Include evidence, confidence, original/native behavior and whether the fix is deferred. It is acceptable to document an issue and defer its fix; record what needs to be revisited. Retain resolved entries and update their status rather than deleting them. Distinguish arithmetic quirks from proven reachable bugs or security vulnerabilities.
- Prioritize a playable original game loop while continuing reconstruction of its actual rules. Preserve unknown fields rather than inventing semantics.
- Use native browser pacing: 1× advances one full game day every four seconds, with the speed slider as a multiplier. The user explicitly requested skipping original PC timing rules; retain recovered timer evidence for reference, without making DOS timing fidelity a prerequisite for usable UI.
- Make all twenty-four supplied crops available in the native game by default; omit crop-file loading and swapping. Keep original sixteen-slot decoding as preservation evidence.
- After the all-crops increment, prioritize original UI, dialogs and gameplay interactions over further background fidelity research. The terrain is a permanent background behind all dialogs, not a window. Remove the Edit titlebar/frame; never raise, hide, resize or close the terrain. Edit shortcuts focus the map without closing floating windows. Closely preserve the original UI layout; display UI artwork at1× to match default terrain scale wherever it fits. The game must remain playable on phones and installable to the home screen in full screen (user request 2026-10-13): windows larger than the screen scale down to fit, and touch placement highlights on the first tap and commits on a second tap. Enhanced graphics/audio are outside the current goal. Keep real HTML/React text and separable components without treating those enhancements as completion requirements.
- Never modify the supplied DOS distribution. Generated original assets stay ignored; import them locally with reproducible scripts.
- Reconstruct UI text as actual HTML/React text elements, including titles, labels, button captions and letter markers. Preserve original artwork/layout without displaying bitmap-based text.
- New Game opens the original region chooser directly and uses fresh startup; do not expose Restart/Start fresh session modes. Retain editable map seed and starting year, with a random seed suggested for each setup. Preserve exact checkpoint loading and original restart evidence/tests.
- Floating windows are movable by their original-style titlebars. Keep the terrain as a fixed background with no titlebar or window controls. Window placement is presentation state, separate from saved simulation state.
- Preserve the original bitmap SIMFARM logo in About and FARM BUREAU logo on the Expert farmer’s cap; the user explicitly requested these exceptions to HTML text. Do not overlay replacement text on these logos.
- Use React state and components for UI controls and text. Keep imperative canvas drawing in `src/render`, with refs for canvas/viewport integration. Global game state belongs to the plain TypeScript simulation, independent of React; UI subscribes to snapshots and sends commands. Do not move simulation rules/state ownership into hooks or a UI store.
- Install dependencies and tools only inside this repository. Use `./tools/bun` (bootstrap: `sh tools/setup-bun.sh`); keep `.cache`, `.tools`, `.venv`, and `node_modules` ignored. Bun's cache and Playwright's browser path must remain local. Commit `bun.lock`, not npm lockfiles; do not require a separate Node installation.
- If `.git` becomes read-only, report the failed Git operation and pause work so the user can unblock it. Do not work around the restriction. Keep commits local unless the user requests a push.
- Use conventional commits in small meaningful increments. Update plans/progress with evidence, checks, limitations, and next actions.
- Use focused validation for each incremental feature: run type checking/production build, relevant decoder/simulation tests, and browser tests covering the changed behavior and directly affected flows. Test binary boundaries and recovered rules, not merely implementation details.
- Do not run both full suites for every feature. Run full regression at meaningful milestones or after a related batch, on user request, or for broad changes to shared rules, binary formats, save schemas, timing/input lifecycle, or cross-cutting architecture. Decide from behavioral impact, not merely whether a shared file was edited. Record the validation scope and any remaining gaps in progress notes.
- Recheck failures with the smallest relevant test set first. After those pass, repeat broader suites only when production changes, unresolved failures or their impact justify it. Keep runtime files fixed during browser runs; avoid redundant full-suite reruns for documentation, test expectations or timeout-only corrections.
