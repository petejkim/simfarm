### Button feedback completion

`useSound.buttonClick` captures eligibility and the transient sound-request counter and returns a completion callback. `WindowDesktop` associates it with the native click event in a weak map during capture, then invokes it after child click handlers in the desktop's bubble handler. Any accepted gameplay or canonical confirmation request during the action supplies its feedback, even while PCM loads; otherwise one ordinary click plays. Counter/callbacks own only presentation, never simulation rules or saved state. Direct Spray confirmations still use the existing click player/preference.

Completion stays synchronous in the activation event, with no timer or task deferral. An initial microtask implementation failed the rooster regressions because browser checkpoints can run between capture and bubble listeners; the final implementation uses the event's bubble phase. Capture checks prevent turning a previously disabled sound preference on from creating a retrospective click; completion checks honor mute or disposal during the handler. Plain navigation never silences an already playing rooster/disaster/plane. Missing effect resources retain the existing error path rather than falling back to a second sound.
