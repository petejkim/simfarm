# Button feedback

User correction2026-10-11: button feedback was only wired in a few original dialog callbacks, so toolbar, palette, purchase and other native buttons were silent. The React desktop now handles enabled button activation once in capture phase, including Enter/Space-generated clicks and nested button text. Disabled/aria-disabled buttons, canvas gestures, title dragging and focus/hover do not trigger this capture handler. Component-local click requests were removed to avoid duplicates; Expert's rooster and canonical gameplay events remain distinct.

Uses the supplied click.voc,2700 bytes, SHA256 `04264e7398f20199cd1cd982a3d00aeaea9dd24e5e945b6315ff6a32cb694510`, decoded through the existing VOC reader to2667 samples at22222.222222Hz. It is not synthesized FM. Uniform button coverage is a requested native presentation policy, not a claim that every original callback made a click sound.

Click feedback has a separate PCM player so it does not stop gameplay effects (including ongoing flight). Both obey the Sound Effects master switch, browser gesture activation, pagehide and cleanup. The decoded click is cached locally; disabled sound suppresses loading/playback, and pending loads abort on mute. Simulation commands, saved state and MIDI remain separate. Keyboard Escape closing a window is not a button activation and does not invoke this policy. No new original-game defect was established.

Requested optimization2026-10-13: each PCM player also caches the Web Audio `AudioBuffer` by decoded-sound identity. The first play allocates the mono buffer and copies the original samples; repeats and overlapping voices reuse it with fresh one-shot source nodes. Mute/stop retain buffers for re-enabling; disposal drops the cache along with the context. Weak keys allow unused decoded sounds and their buffers to be collected. VOC files, sample rates, overlap/voice-limit policy and gains retain their existing behavior. This is a native allocation optimization, not newly recovered DOS behavior; frame-time improvement has not been measured.

The requested native **Button Click Sounds** preference defaults on and is appended after the eight recovered Options entries. Only this dropdown expands to160×112 to fit the ninth actual-text label; original descriptor bytes/tests are retained. Its browser preference key is `buttonClicks` in simfarm.options.v1. It survives reload independently of Sound Effects; the latter still mutes both click and gameplay voices. Turning clicks off aborts pending click loading/stops that voice, without muting ongoing gameplay. Checkpoint loading does not overwrite either audio preference. Disabled storage falls back to a usable current-session toggle through the existing preference handler.
