# Aircraft purchase, service and manual flight

Source SIMFARM.EXE SHA256 `8b86a2d3d07e0b6f77ce491e27e538feeccf5d1af149f42bc0f6a0631c3e58ce`. Addresses are file offsets. Purchase/service and the flight primitives have high-confidence source evidence; manual flight is connected to browser controls, original sprites/PCM and native checkpoints. This is an incremental subsystem reconstruction, not a completed aircraft/game port.

## Purchase

0x30dc6 requires nonzero airport byte DS64c6 and cash at least unsigned equipment-definition8 price (6000 in all supplied farms). The loop scans regionX outer, regionY inner across12×12 and accepts district low nibble5. It chooses local x3 if bit0x20 is clear, otherwise x5 if0x40 is clear, both at local y6. Allocation0x30e70 calls generic0x3a2ca, which calls shared constructor0xf8be. Constructor bytes are the same as ground equipment, including zero fuel/payload/type words20/32/34, preserved unknown bytes and timer DS139e. Definition count and unsigned equipment book value increase; debit category8 increases equipment expenses. No ground-ownership, tree-clearing, strict-cash-equality or generic ground-placement gate applies.

0x30ea1 writes full terrain words71/72 at top row and111/112 at bottom, preserving overlay/attribute separately. The selected regional parking bit is set. Native preflight bounds allocation to1..126 and rejects an inconsistent free-bit/live-aircraft-home collision before mutation. It does not silently search a different pad in that case.

**New airports start with byte0xa5** in constructor0x3aba0, so bit0x20 is already set even when no plane record exists; purchase selects x5. This source fact is preserved, not interpreted as permission to clear a parking bit. Existing aircraft sale/aging cleanup clears its corresponding bit and restores the pad. Tests cover construction→purchase→sale→repurchase at bottom-right map corner and both pads in an explicitly available regional state. DS64c5 is retained in source bytes; the purchase's use of it as a return value is not assumed to mean a plane count.

## Service

The original service dialog opens via parked terrain71/72/111/112 at0x257b0 and equipment lookup. Native accepts active type8 at its intact parked home and refuses busy/incoherent records. Fuel/payload outside0..255 reject service without altering their retained bytes (SF-104). No ground-machine repair is added.

- Fuel0x309ac: low16((255−word20)×DS65f6), initialized rate1. On nonzero successful debit, word20 becomes255.
- Repair0x30d38: low16(condition byte17×signed DS65f8), initialized rate10. Nonzero successful payment zeroes byte17; age word18 survives.
- Payload load0x30cda: full32((255−word32)×floor(selected chemical price/10)). Nonzero payment sets word32=255 and word34=shared selected type.
- Chemical selection0x30a08/0x30a7e/0x30ae4: choices221/223/222. A different selection refunds low16(current payload×prior shared selection unit price), zeroes payload, then changes the global selection. Loaded type word34 is unchanged until the next paid load. Selecting the same type does nothing. Original payload prices are200 in all eight source farms, so full load costs5100; this differs from field treatment delivery pricing.
- All payments use category−1, DS3eac other expenses. Refund0x1ca28 subtracts from this account modulo32bits and adds to cash modulo32bits before the9,999,999 cap. Zero payment never replenishes a free payload (source nonzero-result test).

Shared selection DS65fa/65fc starts at221, independently of each aircraft's payload type. It is simulation state, not React-owned state. This source quirk and possible unequal-price consequences are retained under SF-109. The current implementation stores only the semantic type; the executable far pointer is derived from that type and is never executed or stored as a native pointer.

## Manual-flight rules and clock integration

Manual flight0x30f70 gates iterations on unsigned animation-tick delta≥2 at0x31053. Independent wear/fuel deltas must exceed32 (0x31131/0x3115d): condition increments by one and ends flight above250; fuel decrements as a word, then signed≤0 clamps to0 and ends flight. Active spraying checks delta>8 and consumes one payload unit (0x31190..0x311c6). Its first timestamp is uninitialized (SF-110); the native primitive initializes it to the takeoff animation tick.

The11-word key dispatch table at0x31274 covers codes0x47..0x51:47 toggles spray,49 increments the bounded1..100 sprite-offset/height byte,4a stops spraying,4b/4d decrement/increment heading modulo8,4c/4f end flight,4e starts spray if payload exists,51 decrements the offset and ends at0;48/50 do nothing. Helpers0x631d/0x6338 use BIOS int16 AH1/AH0. Dispatch requires the low ASCII byte to be zero: extended Home toggles spray, PageUp climbs, Left/Right turn, End terminates, and PageDown descends. The scan-table plus/minus entries do not prove that ordinary ASCII-producing keypad keys dispatch. Movement is expressed through viewport origin plus signed local offsets and edge heading changes, not ordinary equipment movement. Native flight coordinates/rendering must disentangle those viewport dependencies.

Every fourth spraying frame (0x31645) finds the field under the computed plane ground position. Loaded type word34 selects221/222/223 effects at0x31682, sharing field-condition helper15b3:1b16 and shifting the corresponding retained byte+60/+61/+62. The primitive applies toxicity mode3 amount2, then mode8/10/6 using the current field byte20/21/22, then halves retained pressure byte60/61/62. Tests check all three loaded types without purchasing ground supplies. Flight end0x317b0 checks whether the current region low nibble is5: airport exit repaints the plane's original home and marks its pad; non-airport exit paints crash tiles73/74/113/114, clears home, invokes generic equipment removal and clears parking. Aircraft record position is not the flight's transient position. Original plane/spray resources and timer updates are now traced below. Live rendering and native engine PCM delivery are described below.


### Source timing, viewport and ending details

Both original timer words DS139e/13a0 increment together at0x625d/0x6261. The modal flight loop does not call the ordinary farm calendar/equipment/field phase driver; native integration advances both logical timer words while suspending ordinary phases. No equivalence between browser wall time and DOS hardware timing is claimed. A queued command is consumed after resource timers and before movement; even an ending input still moves and applies that iteration's spraying before final cleanup. An empty initial fuel tank does not end until its first >32-tick fuel gate. Decrement wraps then clamps signed≤0; wear increments as a byte, including255→0 (SF-104). Spraying can consume its last unit and remain enabled until the following >8-tick check; this is retained.

Centering0x22578 starts camera origin at equipment position minus half the viewport, bounded to the map. Source movement0x31292..0x314c2 changes camera coordinates until its edge, then local plane offsets. The native primitive captures whole-cell viewport dimensions8..80 and excludes DOS client-border offsets. These are explicit native input bounds, not recovered DOS window limits. Horizontal local limit is floor(columns/2)−3; vertical is floor(rows/2)−3. The southern camera edge is95−rows, while the eastern edge is96−columns; edge turns retain the source asymmetries. NW's wrong-axis horizontal clamp is corrected under SF-111. Source initial centering can put the plane away from its parked ground position at a clamped viewport edge; the primitive retains that calculation.

The equipment record remains at its home while transient flight coordinates move. Generic takeoff erase0x1d0e8 replaces each home terrain word with `(old & 0xf800) | (15 + soilMoisture + (attribute >>> 2))`, truncated to16bits. Regional parking stays reserved. Ending over **any** airport region returns the plane to its original home rather than relocating it to that airport. Elsewhere, original crash tiles overwrite the current2×2 footprint; generic removal0x3a040/0xf888 subtracts an owned plane's count and full unsigned price from book value, clears its home/parking and deactivates it, without a cash refund or sale income. Primitive tests cover ending by pilot, zero altitude, fuel and wear, and both home/different-airport return.

The tornado reaction at0x316e8 calls distance helper0x378f8→0xfb54 using camera centre, excluding plane edge offsets. Squared distance<50 starts turbulence; <5 also ends flight at zero altitude. The spin increments on subsequent frames and expires after128ticks. This reaction now receives live canonical tornado state; source-gated disaster updates run on accepted flight iterations (see disasters.md and native v13). The original also calls disaster update24e6:0fb0 and retains spin/turbulence globals DS6620/6624/6626 across flights. The primitive currently initializes those per flight: global carryover remains a fidelity gap. The live dispatcher integration does not complete the remaining disaster types.

### Browser controls and presentation

Buy a Crop Duster through **Buy → Machinery**, then click the parked plane. Use its service icons to refuel/load and **FLY!** to take off. The service panel closes after successful takeoff, and always-visible flight controls appear above the map. Left/Right steer, PageUp/PageDown change altitude, Home toggles spraying, and End ends the flight when the map or a flight button has focus. Equivalent buttons support pointer/touch input. Inputs queue for the next source iteration; paused Step flight executes at most two ticks. The interface explains that ending over an airport lands and ending elsewhere loses the plane. Field actions, service/purchases, loans and Next day are disabled while flying. The existing speed slider continues to control native pacing.

FarmMap refs capture actual client dimensions divided by16×zoom, rounded down and bounded8..80, immediately before start. These dimensions become canonical checkpoint state. Browser resizing/zooming never reinitializes the flight. A ResizeObserver and layout effects keep the visible plane centred (subject to map bounds), even while paused; this is native viewport presentation, not emulation of the source window manager. The original transient camera/edge offsets still determine movement and crop hit tests. Canvas drawing stays in src/render; React owns controls/text and subscribes to detached simulation snapshots.

GameSimulation emits one transient plane-sound request for each completed source iteration, independently of sound enable state. The supplied plane.voc has12848 mono U8 samples at1000000/181 Hz (2.325488seconds); a test pins its archive hash/name/gate instructions and compares every decoded sample. Native engine playback waits while a PCM source or load is active, caches the decoded engine sample, and starts another whole clip on a later flight request after playback ends. It therefore does not restart at every simulation frame. Other effects retain their existing replacement policy. This is a documented native arbitration approximation: driver status2's complete semantics, priority across original effects and end-of-flight DOS audio lifetime remain unverified.

Pause, mute, ending flight and farm replacement stop/cancel engine playback; paused manual steps remain silent. Loading a paused flight does not autoplay. Missing engine data reports an error once per running attempt instead of requesting it every frame; resume or re-enabling sound permits recovery. Neither audio errors nor mute alter simulation state or RNG. These lifetime/retry choices are native accommodations. MIDI remains separate; no FM synthesis or DOS driver is used.

Four Chromium flows cover actual takeoff/captured dimensions, keyboard and button controls, source-exact composited sprites, paused resize/zoom, crop treatment, queued-input save/reload, home return, crash cleanup,390px layout, audible engine samples, non-restarting clip intervals/cache, pause/mute/load cleanup and missing-file recovery. ## Native flight controls and pacing (2026-10-12, user requests)

- **No interim screens:** the in-flight panel (status, control buttons, pause/step) and the post-flight "returned / crashed and was lost" line are removed. The map no longer shrinks during flight. Pause and resume use the ordinary Speed window. The simulation's `step-flight` command remains for tests and checkpoints.
- **Keys:** S climbs, W descends, A/D turn, E ends the flight and Space toggles spraying. They are matched by physical key (`event.code`), so other keyboard layouts work, and they apply wherever focus is except form fields (`src/ui/flight-keys.ts`; listener in `FarmView`). Space's key-up is suppressed during flight so it never presses a focused button.
- **Held keys:** browser auto-repeat is ignored. A held turn/altitude key repeats every 120 ms, but only once the flight has consumed the previous control. The queue therefore never floods and dispatches stay rare; repeated keydowns caused stutter because every dispatch republishes a full snapshot. Space and E fire once per press.
- **Speed:** takeoff sets the speed multiplier to 0.5× (`FLIGHT_SPEED`) and stores the previous speed in the flight as `resumeSpeed`, beside `resumePaused`. Every flight end (landing or crash) restores it. A speed chosen mid-flight lasts only for that flight. Saves store `resumeSpeed` with no version bump; older mid-flight saves without it return to the speed they were saved with, and invalid values are rejected.
- **Shadow:** the original draw order (0x31533..0x31645) paints the airplane, then the shadow, so the shadow covered the aircraft where they overlapped. Native rendering draws the shadow first. This is a presentation deviation; whether the DOS blitter's masking made the original look different is unverified.

Validation: full unit suite 948/948. Flight unit tests now pin 1× for original timing, and a new test covers 0.5×, restore, mid-flight saves and legacy saves. The aircraft-flight browser spec was reworked for keys, Speed controls and frozen-clock frame mirroring; it adds held-key throttling, Space focus and held turning checks. Aircraft-window and sound specs pass (11/11). Production build passes. The full browser suite was not rerun.

## On-screen flight overlay (2026-10-14, user request)

The original flew by keyboard only and drew no flight panel. Native flight now adds a fixed translucent overlay over the terrain (`src/ui/FlightOverlay.tsx`). It is not a movable window, joins no window stacking and is not saved. Floating windows and dialogs stay above it. It exists only while `aircraftFlight` is set and replaces none of the "no interim screens" decisions above: the map keeps its size and there is still no result screen.

- **Readouts (all devices):** altitude (1..100), heading (N…NW; index 0..7 runs clockwise from north per `moveFlight`), fuel, loaded chemical with payload, damage, and what **End** would do now. Fuel/payload/damage are the raw 0..255 record bytes shown as percentages of 255. "End lands at airport" uses the same airport-region test as `finishFlight` (current ground position's region low nibble 5); otherwise it reports "crashes plane". `aircraftFlightView` in `src/simulation/aircraft-view.ts` derives them from the snapshot; React only formats them.
- **Text and stable widths:** readouts and key hints use 10px text (touch-button captions stay 13px). Each changing value, and the Spray/Spraying label, occupies the width of its widest possible text (all eight headings, `100`, `100%`, each chemical at `100%`). Hidden copies share the value's grid cell, so changes such as W → NW never shift later readouts, independent of font metrics.
- **Fine primary pointer (desktop):** key hints (A/D turn, S climb, W descend, Space spray, E end); no buttons.
- **Coarse primary pointer (`(pointer: coarse)`, phones and tablets):** 52 px round buttons. Bottom-left, climb/descend sit above turn left/right; the spray toggle (`aria-pressed` follows `spraying`, disabled with an empty hopper) and End sit bottom-right. All four arrows are one inline SVG triangle (`currentColor`, rotated), because text glyphs ◀ ▶ ▲ ▼ rendered as a mix of colour emoji and plain symbols on phones. They keep clear of the readouts and the centred plane in phone portrait and landscape. End is immediate, like E.
- **Input:** keys and buttons share `createFlightInput` (`src/ui/flight-input.ts`), keyed by source (key code or `pointer:<id>`). Rules are unchanged: dispatch on press; held turn/altitude controls repeat every 120 ms only once the previous control was consumed; spray/End fire once. Buttons capture their pointer, `preventDefault` the press (no focus, so Space still sprays and focus stays put), and release on pointer up/cancel/lost capture. Window blur and flight end release everything. Held appearance is React state, because touch browsers drop `:active` on a held, default-prevented press. Only the buttons take pointer input; touches elsewhere, readouts included, reach the terrain. Keyboard/assistive clicks (no pointer press) send one control.

Validation: `tests/flight-overlay.test.ts` (press/repeat/consumption gating, multi-source holds, one-shot spray/End, release on flight end, readout values/headings/landing test). Browser: `aircraft-flight.spec.ts` checks the desktop overlay (key hints, no buttons, readouts after steering, removal on landing). `flight-touch.spec.ts` (390×844 touch, then 844×390) checks taps queueing exactly one control without focus, a real held CDP touch turning repeatedly while running, readouts, spray state, no queue build-up after release, layout clearance and an End outcome matching the readout. Screenshots `artifacts/browser-flight-touch-{portrait,landscape}.png` and `artifacts/browser-flight.png` were inspected. Physical phones/iOS Safari were not tested.

## Aerial fertilizer (2026-10-14, native addition, user request)

The original plane offers only chemicals 221..223 (handlers 0x30a08/0x30a7e/0x30ae4; no fertilizer control or flight branch). Natively, fertilizer 220 joins `AIRCRAFT_CHEMICALS` and follows the original chemicals' service rules exactly: shared selection DS65fa/65fc semantics, full-load price `(255 − payload) × floor(price/10)` (5100 at the supplied price 200), refunds at the prior selection's price (SF-109 unchanged), word+34 written only on paid loading.

In flight, every fourth spraying frame over a field (the same hit cadence and position test as the other chemicals) applies the **ground fertilizer effect** from treatment completion: `changeFieldCondition` mode1 with 255. Nutrients +29/+30/+31 and regional channel6 saturate at 255, so the first hit equals a ground pass and later hits change nothing. Like ground fertilizer, it adds **no toxicity** and leaves pest/weed/fungus levels and retained pressures untouched. This mirrors the sprays, whose per-hit main effect is also the full ground effect. Payload consumption, pricing and cadence are unchanged.

Saves: `aircraftService.selectedChemical` now accepts 220..223, with no version bump. Older saves remain valid; a save with 220 selected is rejected by builds before this change. Loaded word+34 is not separately validated, as before.

Validation: `tests/aerial-fertilizer.test.ts` covers selection/load price/refund, the per-hit effect with cap, no toxicity/pest/pressure change, no cash change, and checkpoint bounds 219/224 rejected and 220/223 accepted. Older tests that used 220 as an invalid example now use 219/224. Full unit suite passes; the aircraft-window, aircraft, aircraft-flight, flight-touch and crop-supplies browser specs pass.
