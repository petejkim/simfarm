# Supplied XMIDI sequence loops

The eight supplied archive tracks contain only one sequence with AIL loop controls: genfarm.xmi. Its metadata contains eight FOR116/value0 commands at tick0, another at59, then nine NEXT117/value100 commands at7199; end-of-track is7435. Other tracks contain tempo/time-signature/key metadata but no AIL loop controls. Existing fixed120Hz event timing is unchanged. Static import preserves the original linear events and metadata for analysis and MIDI export.

Driver evidence is the immutable supplied SOUND/GMT32MPU.ADV (10843 bytes), SHA256 `3b3c22aae5578a0ca58b792d629912471f1d13527fcf16ba91f3a4f8152bf368`. It is inspected as bytes, never executed. File1980/1984 compare controller numbers116/117 and dispatch through19df/19e1. FOR1a41 sets index0/count4, scans loop counters at sequence+60 forffff, and returns without adding anything if all four slots are occupied.1a55 stores the count and1a5a..1a60 captures the sequence event pointer at+c into corresponding+50 entries. NEXT1a66 ignores values below64;1a6e scans occupied slots backward from6,1a82 treats count0 as infinite, otherwise decrements and releases a slot on zero.1a95..1a9d restores the selected pointer. Loop state is sequence-wide, not per MIDI channel. Range1a41..1aa3 exclusive SHA256 `5ba19315ec5b6ec28884a332ff68ccc6b8f9fb48aa524bc0288d603961ac621a`.

Consequently the first NEXT in genfarm returns to the fourth FOR at tick0; the subsequent FORs were ignored after four slots filled. The ordinary linear end and later NEXT commands are not reached in that infinite iteration. Note durations extend beyond the7199 boundary and must retain their scheduled releases while the next iteration begins. Restarting the entire sequence at7435 plus a release gap/reset is not equivalent: it repeats earlier setup and changes both the boundary and release behavior.

The native decoder now emits an optional loop descriptor with start/end ticks and the events generated within that body, retaining duration-generated releases beyond the end. The original linear event list remains intact for finite MIDI export and analysis. Finite loops, indirect controls and callbacks remain explicit decoder errors rather than silently flattened behavior. Nonadvancing infinite loops reject to prevent an eventual browser scheduler spin. Nested finite loops and arbitrary imported music are not claimed supported. The supplied song needs only the first infinite loop after the driver's four-slot rule.

This increment recovers the loop for the native player; playback still needs to consume it. The player must schedule initial events through the first boundary, retain release tails, repeat only the loop body without a channel reset or gap, and cancel all outstanding events on replacement/mute/disposal. Keep the user's amain-once→genfarm policy. Test scheduling with short synthetic loops before browser integration, plus real track boundaries and lifecycle cancellation.

The [original AIL format manual preserved in WildMIDI](https://github.com/Mindwerks/wildmidi/blob/master/docs/formats/XMIFileFormat-AIL.txt) corroborates sequence-wide FOR/NEXT and four-level nesting. Implementation decisions above use the supplied driver's actual instructions, including its below64 behavior rather than assuming all descriptions apply identically. See SF-176 for that discrepancy. No source distribution changes or emulation.
